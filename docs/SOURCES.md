# Sources

What this repo took from where. Dates are the date of publication or of the last check (September 2026).

## Posts that seeded the repo

- George Pickett, [interrogation prompt](https://x.com/georgepickett/status/2095979879137460640) (Sep 4, 2026): "Think from first principles... is anything unnecessary, over-complicated, or based on weak assumptions? What can be deleted entirely? What can be simplified now that unnecessary pieces are gone? Prefer deleting over simplifying, simplifying over optimizing, optimizing over automating. It might be done too." Became `/interrogate` and step 5 of the core loop.
- Emanuele Di Pietro, [repository audit prompt](https://x.com/emanueledpt/status/2096366700560363931) (Sep 5, 2026): "Audit this repository for low-value code: redundant tests, trivial wrappers, dead abstractions, duplicate helpers, stale comments, unnecessary ceremony. Verify each removal is safe, make the smallest cleanup, run focused tests and lint, and report what changed with evidence. Inspect every major directory before finishing." Became `/deslop`'s scope rule, verification rule, and completion criterion.
- Ben Vinegar, [cyclomatic complexity audits](https://x.com/bentlegen/status/2092606355685216425) (Aug 26, 2026): a 25-line, four-branch block with five narration comments collapsed to two lines and one intent comment; 91 decision paths to 12. The before/after is the model for the complexity budget.
- Alex Graveley, [quote post](https://x.com/alexgraveley/status/2092647694816707042) (Aug 26, 2026): "Just tell the LLM it has to pass cyclomatic complexity lint and it will write simpler code." Became `/clean-code-setup`.
- Manish Kumar, [anti-slop announcement](https://x.com/Manixh02/status/2095720583006974439) (Sep 4, 2026), pointing at [miqdadbadjuber/anti-slop](https://github.com/miqdadbadjuber/anti-slop): rule tiers (hard gate, purpose gate, quality lock), a delivery gate, and the `antislop-code` comment catalog (Tell / Why / Fix). The comment tells in `RED-FLAGS.md` and `COMMENTS.md` follow its shape.
- Matt Pocock, [@mattpocockuk](https://x.com/mattpocockuk). See the next section, and the fourth pass for his 2026 posts.
- Addy Osmani, [@addyosmani](https://x.com/addyosmani), Andrej Karpathy, [@karpathy](https://x.com/karpathy), Vinh Nguyen, [@vinhnx](https://x.com/vinhnx), klöss, [@kloss_xyz](https://x.com/kloss_xyz): see the fourth pass.

## Second pass (2026-09-07)

- Dillon Mulroy, [dmmulroy/anti-slop](https://github.com/dmmulroy/anti-slop): fifteen Oxlint rules rejecting "low-evidence" TypeScript: `no-widen-then-assert`, `no-chained-type-assertions`, `no-unknown-parameters` / `-returns` / `-type-aliases`, `no-unsafe-dictionary-type`, `no-known-value-widening`, `no-runtime-typeof`, `no-module-mocking`, `no-reflect-get` / `-apply`, `no-object-parameters`, `no-shape-in-symbol-names`, `require-safety-comment-for-type-assertion`. Adopted: the evidence framing in the core Types rules and `RED-FLAGS.md`, the `SAFETY:` marker, the module-mocking tell in `TESTS.md`, and the vendoring offer in `/clean-code-setup`. Not adopted as prose rules: `no-shape-in-symbol-names` and `no-object-parameters` (taste, and Oxlint enforces them better than a sentence would).
- Ben Vinegar, [modem-dev/hunk#857](https://github.com/modem-dev/hunk/pull/857) and [#861](https://github.com/modem-dev/hunk/pull/861) (Aug 26, 2026): the refactor behind the "91 to 12" post (split a dispatcher into focused parsers, 130 tests unchanged) and the follow-up ceiling (`complexity: ["error", { max: 80 }]`, just above the current maximum of 78, validated with an 80-passes / 81-fails probe, to be ratcheted down). Adopted: `/deslop` pass 9, the ratchet wording in `/clean-code-setup`, the probe as a completion criterion.
- SprocketLab, [SlopCodeBench](https://arxiv.org/abs/2603.24755) (Mar 2026): structural erosion (complexity mass in functions with CC over 10) and verbosity (AST-grep-flagged plus cloned lines over LOC); agent code 2.0x more eroded and 2.3x more verbose than human repos; an anti-slop prompt cut initial verbosity by up to 34.8% and erosion by 62.3% but did not stop per-iteration degradation; recommendation to schedule refactoring checkpoints and monitor continuously. Adopted: `scripts/complexity.sh` (a CC-weighted erosion approximation), the `Complexity` line in every report, and the "refactoring checkpoint" recipe in `docs/USAGE.md`.
- Competitor skills read for [docs/COMPARISON.md](COMPARISON.md): [wondelai clean-code](https://github.com/wondelai/skills), [Dimillian review-and-simplify-changes](https://github.com/Dimillian/Skills), [PaulRBerg code-polish and fresh-eyes-sweep](https://github.com/PaulRBerg/agent-skills), [ertugrul-dmr clean-code-skills](https://github.com/ertugrul-dmr/clean-code-skills), and Claude Code's bundled `/simplify` (description and phase structure read from the installed binary).

## Third pass (2026-09-07): whole-repo automation and `/finish`

- Anthropic, [Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) (Nov 2025): an initializer that writes a feature list and a progress file, then a coding agent woken repeatedly to do one unit of work, test it, commit it, and update the progress file, because "each new session begins with no memory of what came before" and an agent asked to do too much at once leaves the environment half done. Adopted: `.deslop/plan.md` as the only state, one slice per fresh-context worker, one commit per slice, resume from the plan.
- Google, [*Software Engineering at Google*, ch. 22, Large-Scale Changes](https://abseil.io/resources/swe-book/html/ch22.html): a change too large to submit atomically is sharded along project boundaries; "individual shards should be committable independently"; each shard is tested and submitted on its own. Adopted: slices bounded by module, committable and revertible one at a time.
- Kent Beck, *Tidy First?* (2023): structural and behavioural changes in separate commits; as few tidyings per pull request as possible; Martin Fowler, *Refactoring*: "make each refactoring step as small as possible, so that you can always see the program working" (also the rule behind Matt Pocock's `request-refactor-plan`, which breaks a refactor into "the tiniest commits possible", each leaving the codebase working). Adopted: `refactor(deslop): <slice>` commits that contain cleanup only, with the report as the body.
- Matt Pocock, `improve-codebase-architecture` (mattpocock/skills v1.2.0): weight the parts of the codebase that recently changed, found through `git log`, because deepening pays off where change happens. Adopted: churn as an ordering key for slices.
- Claude Code docs, [Subagents](https://code.claude.com/docs/en/sub-agents) and [Run Claude Code programmatically](https://code.claude.com/docs/en/headless): the Agent tool gives a worker its own context window and returns a summary; `disable-model-invocation` skills cannot be preloaded into subagents, so the worker reads the skill file by path; subagents run in `claude -p` when `Agent` is in `--allowedTools`. Adopted: the worker prompt in `REPO.md` and the inline fallback for hosts without subagents.

## Fourth pass (2026-09-08): senior level, bugs and security, tests that bite, automation

The user's brief for 2.0.0: analyze a set of accounts and posts, draw the rules out of them, and turn the skill set from "removes slop" into "writes the code a senior would have written, finds what is wrong, fixes it, and runs on its own". Every post below was fetched verbatim (through the fxtwitter API and the syndication endpoint; timeline mirrors were blocked on the machine used, so threads and replies are not covered).

- Vinh Nguyen, [go-to review prompt](https://x.com/vinhnx/status/2096567973012197733) (Sep 6, 2026): "Review the full diff and nearby code. Find real bugs, regressions, and unnecessary complexity. Reuse existing patterns, rank issues by severity, filter false positives, apply DRY/KISS refactors, fix, test, and re-review until clean." Adopted: the review reads the code around each hunk, not only the hunks; `/finish` runs review, apply, review as a bounded loop (two rounds); "reuse existing patterns" became the copy-of-existing-helper flag and the "repo's secure pattern first" rule in `/audit`.
- Matt Pocock, [CODING_STANDARDS.md and /code-review](https://x.com/mattpocockuk/status/2088256432265167185) (Aug 14, 2026): "Notice the agent is doing something bad. Write it in CODING_STANDARDS.md. /code-review picks it up and enforces it at review time. I have hundreds of lines in my CODING_STANDARDS.md files." Adopted earlier as the standards file; now also the "offer one dated line after every correction" rule in `clean-code` and the `CLAUDE.md` snippet.
- Matt Pocock, [tautological tests](https://x.com/mattpocockuk/status/2093068185830347088) (Aug 27, 2026), quoting Emma De Silva's screenshot of a Pest test that reads `app.css` and asserts it contains three strings: `echo "Tautological tests considered harmful." >> CODING_STANDARDS.md`. Adopted: the "artifact asserts itself" tautology in `TESTS.md` and `RED-FLAGS.md`, the line in the `CODING_STANDARDS.md` template, and the delete verdict in `/test-audit`.
- Matt Pocock, [the drawer of cables](https://x.com/mattpocockuk/status/2097238983226868194) (Sep 8, 2026): "If you give an agent a markdown file, it will eventually fill it with: unnecessary implementation details, session-specific observations, stale docs." Adopted: the "Instruction files" section of `clean-code`, the sediment flags in `RED-FLAGS.md`, and `/deslop` pass 11 (docs and instruction files), with the docs as their own last slice in `repo` mode.
- Matt Pocock, `diagnosing-bugs`, `codebase-design` (`DEEPENING.md`), `improve-codebase-architecture`, `tdd` (`tests.md`, `mocking.md`), `code-review`, `writing-great-skills` (mattpocock/skills v1.2.0, read from the installed plugin): the red-capable loop before any hypothesis and "if no correct seam exists, that itself is the finding" (the spine of `/audit` steps 3 and 4); "replace, don't layer" for tests at a deepened interface; dependency categories for deepening; the deletion test; positive phrasing and leading words for skill text.
- Addy Osmani, [Code review in the age of AI](https://addyosmani.com/blog/code-review-ai/), [Agentic code review](https://addyosmani.com/blog/agentic-code-review/), [Software factories](https://addyosmani.com/blog/software-factories/), [Agentic code quality](https://addyosmani.com/blog/agentic-code-quality/), [AGENTS.md](https://addyosmani.com/blog/agents-md/), [Comprehension debt](https://addyosmani.com/blog/comprehension-debt/), [Intent debt](https://addyosmani.com/blog/intent-debt/), [The 70% problem](https://addyo.substack.com/p/the-70-problem-hard-truths-about), and [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills) (`code-review-and-quality`, `test-driven-development`, `security-and-hardening`, `debugging-and-error-recovery`, `constraint-driven-development`) (2024 to 2026). Adopted: "insist on proof, not promises" as the third governing idea and the `Unverified` report line; read test diffs first and the weakened-check flag; tier by risk and the confidence bar; "the safety net has to live outside the model" (types, seams, layout, boundaries, injection) as the "design for the day it goes wrong" section; mutation testing as a constraint; "every line traceable to a failure" and "encode must-hold rules in tests, hooks, or permissions" as the hooks-by-default decision; the senior refactoring pass (smaller modules, edge cases, stronger types, error handling) as `/deslop` pass 9; state-not-interactions and self-contained tests; the security always/ask/never list mapped into `BUGS.md`; "comment the why, the why that does not fit goes in the commit body".
- Andrej Karpathy, [notes from a month of agent coding](https://x.com/karpathy/status/2015883857489522876) (Jan 26, 2026), [on nanochat agents](https://x.com/karpathy/status/2019851952033771710) (Feb 6, 2026), [on code quality](https://x.com/karpathy/status/2035173492447224237) (Mar 21, 2026), [Sequoia Ascent 2026](https://karpathy.bearblog.dev/sequoia-ascent-2026/), [autoresearch `program.md`](https://github.com/karpathy/autoresearch), and the Dwarkesh follow-up on agents (Oct 18, 2025). Adopted: the failure catalog (wrong assumptions run with; overcomplicated APIs and bloated abstractions; dead code not cleaned up; comments and code "cleaned up" without understanding; copy-pasted blocks; "every line of code should do exactly one thing and use intermediate variables as a form of documentation") as gates and flags; "give it success criteria and watch it go" and "write the naive algorithm that is very likely correct first, then optimize" in the loop; "hooks or slash commands" over more prose; the simplicity criterion from `program.md` ("an improvement of ~0 but much simpler code? The multica-ai `andrej-karpathy-skills` CLAUDE.md is the repo author's LLM-drafted interpretation of that post, not Karpathy's text, and is credited as such.

The security section of `BUGS.md` follows this order.
- Mutation testing: [StrykerJS](https://stryker-mutator.io/), [mutmut](https://mutmut.readthedocs.io/), [pytest-gremlins](https://github.com/mikelane/pytest-gremlins), [cargo-mutants](https://mutants.rs/), [gremlins](https://gremlins.dev/).
